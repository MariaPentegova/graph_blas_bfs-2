# Сравнение BFS: Classic vs GraphBLAS

## О проекте

В проекте реализованы и протестированы четыре варианта обхода графа в ширину (BFS):
* **Classic Parent BFS** — классический BFS с очередью и построением массива родителей (`parent`).
* **Classic Multisource BFS** — классический BFS одновременно из нескольких источников.
* **GraphBLAS Level BFS** — BFS, сформулированный через операции линейной алгебры с использованием `SuiteSparse:GraphBLAS`. Результатом является уровень (`level`) каждой достижимой вершины.
* **GraphBLAS Multisource BFS** — аналогичный алгоритм с несколькими исходными вершинами.

**Цель проекта** — сравнить классический алгоритм обхода графа с его линейно-алгебраической реализацией и исследовать зависимость производительности от структуры графа.

---

## Основные возможности

Программа выполняет следующие шаги:
1. Загружает граф из файла формата Matrix Market (`.mtx`).
2. Преобразует граф в CSR-представление.
3. Находит вершину с максимальной степенью.
4. Выбирает четыре источника для multisource BFS.
5. Строит матрицу смежности GraphBLAS.
6. Запускает четыре реализации BFS.
7. Измеряет время выполнения.
8. Позволяет сравнить результаты классического и GraphBLAS-подходов.
9. Содержит набор тестов для проверки корректности реализаций.

## Представление графа

### Matrix Market
Исходные графы загружаются из файлов формата Matrix Market (`.mtx`). Программа поддерживает квадратные матрицы без числовых значений (pattern) в форматах:
* `symmetric` — неориентированный граф;
* `general` — ориентированный граф.

### CSR
После загрузки граф преобразуется в формат CSR (Compressed Sparse Row). CSR хранит списки смежности в двух основных массивах:
* `row_ptr` — массив длины `n + 1`. Для вершины `v` значение `row_ptr[v]` указывает на начало её списка соседей в `col_idx`, а `row_ptr[v + 1]` — на конец;
* `col_idx` — массив, в котором последовательно записаны соседи всех вершин.

**Пример:**
```text
row_ptr = [0, 2, 5, 6]
col_idx = [1, 3, 0, 2, 4, 1]
```
Это означает:
* Вершина `0` → соседи `col_idx[0]`, `col_idx[1]` → `1, 3`
* Вершина `1` → соседи `col_idx[2]`, ..., `col_idx[4]` → `0, 2, 4`
* Вершина `2` → сосед `col_idx[5]` → `1`

Таким образом, соседи вершины `v` находятся в `col_idx` начиная с позиции `row_ptr[v]` и заканчивая позицией `row_ptr[v + 1] - 1`. CSR позволяет компактно хранить большие разреженные графы и последовательно просматривать соседей вершины.

## Реализованные алгоритмы

### Classic Parent BFS
Классический BFS использует очередь. При первом посещении вершины `neighbor` в массив `parent` записывается вершина, из которой она была обнаружена.

```c
void csr_parent_bfs(
    CSRMatrix* csr,
    int start_vertex,
    int* parent
);
```

* Для корневой вершины: `parent[start_vertex] = start_vertex`
* Для остальных достижимых вершин: `parent[neighbor] = текущая вершина`

Массив `parent` задаёт дерево BFS для соответствующей компоненты связности.

**Асимптотическая сложность классического BFS:**
* **Время:** \(O(V + E)\)
* **Память:** \(O(V + E)\)

### Classic Multisource BFS
Multisource BFS использует ту же очередь, но перед началом обхода в неё добавляются все заданные источники.

#### 1. Classic Parent BFS
Классический BFS с использованием очереди. При первом посещении вершины-соседа в массив `parent` записывается вершина, из которой она была обнаружена.
```c
void csr_multisource_bfs(
    CSRMatrix* csr,
    int* sources,
    int num_sources,
    int* parent
);
```
* **Корневая вершина:** `parent[start_vertex] = start_vertex`
* **Остальные вершины:** `parent[neighbor] = текущая_вершина`

Массив `parent` задаёт дерево BFS для соответствующей компоненты достижимости.
* *Сложность по времени:* \(O(V + E)\)
* *Сложность по памяти:* \(O(V + E)\)

Все источники имеют расстояние `0`. Далее BFS распространяется от них одновременно. При первом обнаружении вершины ей назначается родитель, через которого она была достигнута.

### GraphBLAS BFS
GraphBLAS-реализация формулирует BFS в терминах операций над разреженными матрицами и векторами.

Матрица смежности графа обозначается через \(A\). Текущий фронт BFS представляется булевым разреженным вектором `frontier`. На каждой итерации вычисляется следующий фронт:
\[\text{frontier\_next} = \text{frontier} \times A\]

В реализации используется функция `GrB_vxm(...)` и булев полукольцо (semiring) **LOR-LAND**:
* `LAND` используется как операция умножения;
* `LOR` используется как операция сложения.

Для исключения уже посещённых вершин используется маска `visited`. После получения нового фронта он добавляется к множеству посещённых вершин. Таким образом, один уровень BFS соответствует одной итерации матрично-векторного распространения фронта.

### GraphBLAS Level BFS
```c
int graphblas_level_bfs(
    CSRMatrix* csr,
    void* A_handle,
    int start_vertex,
    int* level
);
```
Функция записывает в `level` расстояние от исходной вершины до каждой достижимой вершины. Недостижимые вершины получают значение `-1`.

### GraphBLAS Multisource BFS
В multisource-варианте начальный фронт содержит несколько источников:
\[\text{frontier} = \{source_1, source_2, \dots, source_k\}\]

После этого выполняется тот же итерационный процесс с использованием матрично-векторного умножения.

#### 2. GraphBLAS Multisource BFS
В данном варианте начальный фронт содержит сразу несколько источников: \(\text{frontier} = \{source_1, source_2, \dots, source_k\}\).
```c
int graphblas_multisource_level_bfs(
    CSRMatrix* csr,
    void* A_handle,
    int* sources,
    int num_sources,
    int* level
);
```
Все источники получают уровень `0`, а последующие уровни вычисляются одновременно.

Для разработки могли быть использованы существующие реализации алгоритмов анализа графов, в частности **LAGraph** и **Boost Graph Library (BGL)**. 

Готовые реализации BFS из этих библиотек **не использовались** в финальных измерениях по следующим причинам:
1. **Чистота эксперимента:** Главная цель проекта — напрямую сравнить самостоятельно реализованный обход CSR с реализацией того же алгоритма средствами GraphBLAS.
2. **Исключение побочных факторов:** Использование стороннего готового BFS могло бы внести дополнительные различия, связанные со спецификой конкретных библиотек, внутренними структурами данных и скрытыми оптимизациями. 
3. **Идентичность окружения:** Самостоятельный подход гарантирует, что оба метода используют один и тот же входной граф и одинаковые параметры запуска.

Основные функции модуля `utils`:
* `load_matrix()` — загрузка графа из Matrix Market;
* `graph_to_csr()` — преобразование графа в CSR;
* `find_max_degree_vertex()` — поиск вершины с максимальной степенью;
* `delete_graph()` — освобождение списка смежности;
* `delete_csr()` — освобождение CSR-представления.

Для GraphBLAS дополнительно используются функции инициализации библиотеки, создания матрицы смежности и освобождения её ресурсов.

### Что проверяется в тестах
1. **Изолированная проверка реализаций** (на фиксированных тестовых топологиях):
   * Достижимость вершин и корректность вычисленных уровней BFS.
   * Правильность работы многопоточного/многоисточникового обхода (*Multisource BFS*).
   * Структурная корректность массива `parent` (отсутствие циклов в дереве родителей, валидность корневой вершины).
   * Наличие непрерывной цепочки родителей от каждой посещённой вершины к её исходному источнику.
2. **Перекрёстная (cross-validation) проверка:**
   * **Single-source:** Классический CSR-обход и GraphBLAS запускаются на одинаковых графах из одной и той же вершины. Полученные векторы уровней сравниваются поэлементно.
   * **Multi-source:** Выполняется аналогичное покомпонентное сравнение векторов при идентичном наборе начальных вершин-источников.

*Примечание: Успешное прохождение тестового набора гарантирует соответствие двух разных подходов на заложенных сценариях, но не является математическим доказательством корректности для абсолютно любых произвольных графов.*

## Анализ

* На двух социальных графах (`com-Orkut` и `soc-LiveJournal1`) **GraphBLAS Level** показал существенное преимущество перед классическим BFS: ускорение составило **5.45x** и **5.35x** соответственно.
* На графах `road_usa`, `roadNet-CA`, `cit-Patents` и `com-Amazon` **классический BFS** оказался производительнее. На веб-графе `web-Google` результаты практически совпали.

Одним из ключевых факторов разницы в производительности является **структура фронта BFS**:
* **Широкий фронт:** За одну итерацию обрабатывается большое количество вершин. Это создаёт отличные условия для эффективного применения параллельных матричных операций внутри GraphBLAS.
* **Узкий фронт:** Преимущества матричного представления и векторизации нивелируются, а накладные расходы библиотеки становятся слишком критичными.

>  *В данном проекте размер фронта на каждой итерации непосредственно не измеряется, поэтому влияние этого фактора пока является гипотезой, а не отдельно проверенным экспериментальным результатом.*

Результаты также демонстрируют, что тип графа сам по себе не предопределяет итоговую скорость. Например, `cit-Patents` является ориентированным графом, но классическая реализация на нём значительно обогнала GraphBLAS. Для более точного анализа требуется учитывать совокупность всех топологических характеристик графа.

## Вывод

В проекте успешно реализованы классический и линейно-алгебраический подходы к алгоритму BFS (в одиночном и multisource вариантах). Классическая версия опирается на очередь и CSR-представление, тогда как GraphBLAS-версия формулирует обход как последовательность операций над разреженной матрицей смежности и булевыми векторами фронта.

Эксперимент на семи графах SuiteSparse показал, что эффективность каждого подхода **напрямую зависит от структуры входных данных**. GraphBLAS получил значительное преимущество на социальных графах с высокой плотностью связей, в то время как классический BFS лидировал на дорожных сетях и разреженных структурах.

Для дальнейшего исследования проекта будет полезно внедрить сбор статистики по размерам фронтов BFS на каждом уровне, чтобы сопоставить эти данные с детальным временем выполнения итераций.
