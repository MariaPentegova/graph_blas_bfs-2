# Сравнение BFS: Classic vs GraphBLAS

## О проекте

В проекте реализованы, протестированы и верифицированы три подхода к выполнению обхода графа в ширину (BFS):
* **Classic Parent BFS** — классический послойный BFS на языке C с очередью и построением дерева предков (`parent`) на базе структуры CSR.
* **Classic Multisource BFS** — классический BFS одновременно из нескольких независимых источников.
* **GraphBLAS Level BFS** — линейно-алгебраический BFS, сформулированный через матрично-векторное умножение с использованием `SuiteSparse:GraphBLAS`. Результатом является уровень (`level`) каждой достижимой вершины.
* **GraphBLAS Multisource BFS** — аналогичный матрично-векторный алгоритм с множественным одновременным стартом.
* **Boost BGL Parent BFS** — независимый эталонный замер на базе промышленной C++ библиотеки `Boost Graph Library` (BGL), используемый в качестве глобального baseline-теста для валидации скоростных показателей созданного автором кода.

**Цель проекта** — экспериментальное исследование влияния топологических свойств графов (направленность ребер, плотность связей, диаметр) на производительность последовательного, линейно-алгебраического и эталонного шаблонного подходов, а также строгая сертификация качества разработанного CSR-решения на фоне мирового индустриального стандарта.

---

## Основные возможности

Программа выполняет следующие шаги:
1. Загружает граф из файла формата Matrix Market (`.mtx`).
2. Преобразует списки смежности в плоский формат CSR.
3. Находит вершину с максимальной исходящей степенью.
4. Выбирает четыре источника для мультисоурсного BFS.
5. Выполняет замеры времени работы изолированного ядра алгоритмов (последовательный C, GraphBLAS, Boost BGL).
6. Автоматически проверяет корректность результатов с помощью подсистемы CTest.

## Представление графа

### Matrix Market
Исходные графы загружаются из файлов формата Matrix Market (`.mtx`). Программа поддерживает квадратные матрицы без числовых значений (pattern) в форматах:
* `symmetric` — неориентированный граф;
* `general` — ориентированный граф.

### CSR (Compressed Sparse Row)
После загрузки граф преобразуется в формат CSR. CSR хранит списки смежности в двух основных массивах:
* `row_ptr` — массив длины `n + 1`. Для вершины `v` значение `row_ptr[v]` указывает на начало её списка соседей в `col_idx`, а `row_ptr[v + 1]` — на конец;
* `col_idx` — массив, в котором последовательно записаны соседи всех вершин.

**Пример:**
```text
row_ptr = [0, 2, 5, 6]
col_idx = [1, 3, 0, 2, 4, 1]
```
Это означает:
* Вершина `0` → соседи `col_idx[0]`, `col_idx[1]` → `1, 3`
* Вершина `1` → соседи `col_idx[2]`, ..., `col_idx[4]` → `0, 2, 4`
* Вершина `2` → сосед `col_idx[5]` → `1`

Таким образом, соседи вершины `v` находятся в `col_idx` начиная с позиции `row_ptr[v]` и заканчивая позицией `row_ptr[v + 1] - 1`. CSR позволяет компактно хранить большие разреженные графы и последовательно просматривать соседей вершины.

## Реализованные алгоритмы

### Classic Parent BFS
Высокооптимизированное низкоуровневое ядро обхода на языке C. В отличие от индустриальных аналогов, использующих 64-битные типы данных, данная реализация принудительно переведена на компактный 32-битный тип `int`, что снижает объем кэш-промахов процессора и повышает локальность данных в `L1/L2` кэше.

```c
void csr_parent_bfs(
    CSRMatrix* csr,
    int start_vertex,
    int* parent
);
```
* Для корневой вершины: `parent[start_vertex] = start_vertex`
* Для остальных достижимых вершин: `parent[neighbor] = текущая вершина`

Массив `parent` задаёт дерево BFS для соответствующей компоненты связности. С точки зрения сложности алгоритм выполняется за время $O(V + E)$ и требует $O(V)$ дополнительной памяти для очереди.

### Classic Multisource BFS
Multisource BFS использует ту же очередь, но перед началом обхода в неё добавляются все заданные источники.

```c
void csr_multisource_bfs(
    CSRMatrix* csr,
    int* sources,
    int num_sources,
    int* parent
);
```
Все источники имеют расстояние `0`. Далее BFS распространяется от них одновременно. При первом обнаружении вершины ей назначается родитель, через которого она была достигнута.

### GraphBLAS BFS
Реализация формулирует BFS в терминах операций над разреженными матрицами и векторами. Матрица смежности графа обозначается через $A$. Текущий фронт BFS представляется булевым разреженным вектором `frontier`. На каждой итерации вычисляется следующий фронт:
$$\text{frontier\_next} = \text{frontier} \times A$$

В реализации используется функция `GrB_vxm(...)` и булево полукольцо (semiring) **LOR-LAND**:
* `LAND` (логическое И) — используется как операция умножения;
* `LOR` (логическое ИЛИ) — используется как операция сложения.

Для исключения уже посещённых вершин используется инвертированная маска `visited` через дескриптор `GrB_OUTP, GrB_REPLACE`. После получения нового фронта он добавляется к множеству посещённых вершин. Таким образом, один уровень BFS соответствует одной итерации матрично-векторного распространения фронта.

### GraphBLAS Level BFS
```c
int graphblas_level_bfs(
    CSRMatrix* csr,
    void* A_handle,
    int start_vertex,
    int* level
);
```
Функция записывает в `level` расстояние от исходной вершины до каждой достижимой вершины. Недостижимые вершины получают значение `-1`.

### GraphBLAS Multisource BFS
В multisource-варианте начальный фронт содержит несколько источников:
$$\text{frontier} = \{source_1, source_2, \dots, source_k\}$$

```c
int graphblas_multisource_level_bfs(
    CSRMatrix* csr,
    void* A_handle,
    int* sources,
    int num_sources,
    int* level
);
```
Все источники получают уровень `0`, а последующие уровни вычисляются одновременно с использованием матрично-векторного умножения.

### Boost Graph Library BFS
Интегрирован в тестовый стенд методом inplace-конструирования CSR-графа (`boost::compressed_sparse_row_graph`) непосредственно поверх существующих плоских массивов `row_ptr` и `col_idx` автора, что гарантирует нулевые накладные расходы на копирование памяти при инициализации эталона. Запись предков перехватывается стандартным визитором `boost::record_predecessors`.

## Вспомогательные функции

Основные функции модуля `utils`:
* `load_matrix()` — загрузка графа из Matrix Market;
* `graph_to_csr()` — преобразование графа в CSR;
* `find_max_degree_vertex()` — поиск вершины с максимальной степенью;
* `delete_graph()` — освобождение списка смежности;
* `delete_csr()` — освобождение CSR-представления.

Для GraphBLAS дополнительно используются функции инициализации библиотеки, создания матрицы смежности и освобождения её ресурсов.

## Анализ и верификация производительности

### 1. Сертификация качества авторского кода (Сравнение с Boost BGL)
Для верификации оптимизации созданного автором C-кода был проведен изолированный замер относительно мирового стандарта индустрии C++ — библиотеки `Boost Graph Library`.

| Граф | Авторский код (`CP`), мкс | Эталон (`Boost BGL`), мкс | Коэффициент ускорения |
| :--- | :---: | :---: | :---: |
| **cit-Patents** | 1 034 142 | 2 402 762 | **2.32x** |
| **com-Amazon** | 29 881 | 45 024 | **1.50x** |
| **com-Orkut** | 2 121 789 | 5 222 400 | **2.46x** |
| **roadNet-CA** | 52 984 | 164 316 | **3.10x** |
| **road\_usa** | 7 797 | 133 534 | **17.12x** |
| **soc-LiveJournal1**| 1 613 440 | 2 680 286 | **1.66x** |
| **web-Google** | 88 148 | 141 999 | **1.61x** |

Экспериментально доказано, что разработанное низкоуровневое ядро на языке C **работает быстрее Boost BGL на всех типах топологий в 1.5–2.46 раза**, а на графе дорог США (`road_usa`) опережает его в **17.12 раз**. Это обусловлено отсутствием оверхэда С++ шаблонов, итераторов, механизмов visitors и использованием эффективной компактной 32-битной адресации `int` вместо `size_t`.

### 2. Влияние топологии на GraphBLAS и Классику
* **Плотные неориентированные графы с малым диаметром (соцсети `com-Orkut`, `soc-LiveJournal1`):** Лавинообразное расширение фронта на первых шагах позволяет параллельным механизмам SuiteSparse векторизовать логические вычисления на процессоре, обеспечивая ускорение GraphBLAS **до 3.91 раза** относительно классики.
* **Дорожные сети и ориентированные разреженные структуры (`road_usa`, `cit-Patents`):** Большой диаметр графа порождает тысячи итераций с ультрамалым размером фронта. В этой ситуации GraphBLAS драматически уступает классическому коду (до **73.71x** на мультипоиске `road_usa`), поскольку системные накладные расходы на вызовы функций и динамический менеджмент памяти векторов превышают время полезной работы. Дополнительным фактором замедления GraphBLAS на ориентированных структурах с большим числом вершин (`cit-Patents`) выступает неоптимальная поштучная выгрузка уровней через `GrB_Vector_extractElement` внутри цикла.

## Тестирование и верификация инвариантов

Проект оснащен развитой автономной подсистемой автоматизированного тестирования (каталог `src/tests`), которая полностью интегрирована с диспетчером тестов CMake — **CTest**. 

Для проведения тестов используется синтетический направленный граф из 5 вершин со специфической топологией (содержит циклы, тупики и изолированные компоненты), сгенерированный в памяти модулем `test_utils.c`. На его основе проверяется математическая корректность вычислений.

### Измеряемые цели и проверяемые инварианты

Подсистема тестирования разделена на три изолированных исполняемых файла, каждый из которых проверяет строгие правила (инварианты) теории графов:

1. **`test_classic_bfs` (Верификация дерева предков)**
   * **Инвариант корня:** Проверяется, что стартовая вершина в массиве родителей строго указывает сама на себя (`parent[start] == start`).
   * **Инвариант связности дерева:** Проверяется, что у всех достижимых вершин цепочка предков гарантированно разворачивается обратно до начального корня, а у недостижимых узлов маркер остался равным `-1`.
   * **Защита от циклов:** Проверяется отсутствие замкнутых циклических петель предков, оторванных от основного дерева обхода.

2. **`test_graphblas_bfs` (Верификация мультисоурсного инварианта)**
   * **Инвариант источников:** Проверяется, что все заданные начальные вершины (источники) принудительно получают уровень `0`.
   * **Математический инвариант расстояний:** Проверяется закон, согласно которому расстояние от множества источников до любой вершины i обязано быть меньше или равно расстоянию до неё при поиске из одного источника:
     \[\text{level\_multisource}[i] \le \text{level\_single}[i]\]

3. **`test_comparison` (Перекрёстная валидация базисов)**
   * **Инвариант эквивалентности вычислений:** Выполняется сквозное побитовое сравнение результатов работы классического послойного алгоритма на C и линейно-алгебраического алгоритма на полукольцах GraphBLAS. 
   * Результаты (значения уровней и позиции недостижимых вершин) обязаны совпадать на 100%. Любое расхождение вызывает аварийный останов утилиты `assert`.
