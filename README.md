# Сравнение BFS: Classic vs GraphBLAS

## О проекте

В проекте реализованы и протестированы четыре варианта обхода графа в ширину (Breadth-First Search, BFS):

- **Classic Parent BFS** — классический BFS с очередью и построением массива родителей (`parent`).
- **Classic Multisource BFS** — классический BFS одновременно из нескольких источников.
- **GraphBLAS Level BFS** — BFS, сформулированный через операции линейной алгебры с использованием `SuiteSparse:GraphBLAS`. Результатом является уровень (`level`) каждой достижимой вершины.
- **GraphBLAS Multisource BFS** — аналогичный алгоритм с несколькими исходными вершинами.

**Цель проекта** — сравнить классический алгоритм обхода графа с его линейно-алгебраической реализацией и исследовать зависимость времени выполнения от структуры входного графа.

GraphBLAS предоставляет программный интерфейс для представления графовых алгоритмов в терминах операций над матрицами и векторами. В проекте используется реализация GraphBLAS из состава SuiteSparse. Спецификация GraphBLAS описывает обобщённые матричные и векторные операции, включая операции над полукольцами, которые применяются для формулировки алгоритмов анализа графов.  
[GraphBLAS C API Specification](https://graphblas.org/docs/GraphBLAS_API_C_v2.1.0.pdf)

---

## Основные возможности

Программа выполняет следующие шаги:

1. Загружает граф из файла формата Matrix Market (`.mtx`).
2. Определяет тип графа по заголовку Matrix Market.
3. Преобразует граф в CSR-представление.
4. Для однократного BFS выбирает вершину с максимальной исходящей степенью.
5. Выбирает четыре источника для multisource BFS.
6. Строит матрицу смежности GraphBLAS.
7. Запускает четыре реализации BFS.
8. Измеряет время выполнения.
9. Сравнивает результаты классического и GraphBLAS-подходов.
10. Запускает автоматические тесты корректности реализаций.

# Анализ и сравнение реализаций алгоритма BFS

Репозиторий содержит самостоятельные реализации алгоритма поиска в ширину (BFS) на основе классического обхода списков смежности в формате **CSR** и матрично-векторных операций средствам библиотеки **GraphBLAS**.

---

##  Представление графа

### Matrix Market
Исходные графы загружаются из файлов формата **Matrix Market (`.mtx`)**. Программа использует квадратные матрицы без числовых значений (*pattern*) со следующими типами симметрии:
* **`symmetric`** — матрица симметрична, граф рассматривается как неориентированный.
* **`general`** — матрица не обязана быть симметричной, граф рассматривается как ориентированный.

>  Для матриц с типом `general` каждая координатная запись соответствует одной дуге исходного графа. Перед выполнением BFS направление дуг не изменяется.

### CSR (Compressed Sparse Row)
После загрузки граф преобразуется в формат **CSR**, который хранит списки смежности в двух основных массивах:
* **`row_ptr`** — массив длины \(n + 1\). Для вершины `v` значение `row_ptr[v]` указывает на начало её списка соседей в `col_idx`, а `row_ptr[v + 1]` — на конец.
* **`col_idx`** — массив, в котором последовательно записаны соседи всех вершин.

**Пример:**
```python
row_ptr = [0, 2, 5, 6]
col_idx = [1, 3, 0, 2, 4, 1]
```

Это означает:
* Вершина **0** имеет соседей: `1`, `3`
* Вершина **1** имеет соседей: `0`, `2`, `4`
* Вершина **2** имеет соседа: `1`

Таким образом, соседи вершины `v` находятся в массиве `col_idx` начиная с позиции `row_ptr[v]` и заканчивая позицией `row_ptr[v + 1] - 1`.

##  Реализованные алгоритмы

### Классический BFS (на базе CSR)

#### 1. Classic Parent BFS
Классический BFS с использованием очереди. При первом посещении вершины-соседа в массив `parent` записывается вершина, из которой она была обнаружена.
```c
void csr_parent_bfs(
    CSRMatrix* csr,
    int start_vertex,
    int* parent
);
```
* **Корневая вершина:** `parent[start_vertex] = start_vertex`
* **Остальные вершины:** `parent[neighbor] = текущая_вершина`

Массив `parent` задаёт дерево BFS для соответствующей компоненты достижимости.
* *Сложность по времени:* \(O(V + E)\)
* *Сложность по памяти:* \(O(V + E)\)

#### 2. Classic Multisource BFS
Использует ту же логику и очередь, но перед началом обхода в неё сразу добавляются все заданные источники.
```c
void csr_multisource_bfs(
    CSRMatrix* csr,
    int* sources,
    int num_sources,
    int* parent
);
```
Все источники имеют начальное расстояние `0`, и BFS распространяется от них одновременно.

---

### GraphBLAS BFS
Реализация формулирует BFS в терминах операций над разреженными матрицами и векторами. Матрица смежности графа обозначается как \(A\). Текущий фронт представляется булевым разреженным вектором `frontier`. На каждой итерации вычисляется следующий фронт:

\[\text{frontier\_next} = \text{frontier} \times A\]

В реализации используется функция `GrB_vxm(...)` и булево полукольцо **LOR-LAND**:
* **`LAND`** (логическое И) — операция умножения.
* **`LOR`** (логическое ИЛИ) — операция сложения.

Для исключения уже посещённых вершин используется маска `visited`. Одна итерация матрично-векторного распространения соответствует переходу BFS на следующий уровень.

#### 1. GraphBLAS Level BFS
Записывает в массив `level` расстояние от исходной вершины до каждой достижимой. Недостижимые вершины получают значение `-1`.
```c
int graphblas_level_bfs(
    CSRMatrix* csr,
    void* A_handle,
    int start_vertex,
    int* level
);
```

#### 2. GraphBLAS Multisource BFS
В данном варианте начальный фронт содержит сразу несколько источников: \(\text{frontier} = \{source_1, source_2, \dots, source_k\}\).
```c
int graphblas_multisource_level_bfs(
    CSRMatrix* csr,
    void* A_handle,
    int* sources,
    int num_sources,
    int* level
);
```
Все источники получают уровень `0`, а последующие уровни вычисляются одновременно.

##  Почему BFS реализован самостоятельно

Для разработки могли быть использованы существующие реализации алгоритмов анализа графов, в частности **LAGraph** и **Boost Graph Library (BGL)**. 

Готовые реализации BFS из этих библиотек **не использовались** в финальных измерениях по следующим причинам:
1. **Чистота эксперимента:** Главная цель проекта — напрямую сравнить самостоятельно реализованный обход CSR с реализацией того же алгоритма средствами GraphBLAS.
2. **Исключение побочных факторов:** Использование стороннего готового BFS могло бы внести дополнительные различия, связанные со спецификой конкретных библиотек, внутренними структурами данных и скрытыми оптимизациями. 
3. **Идентичность окружения:** Самостоятельный подход гарантирует, что оба метода используют один и тот же входной граф и одинаковые параметры запуска.

*Примечание: Библиотека LAGraph использовалась исключительно как источник информации о способах формулировки графовых алгоритмов через концепции линейной алгебры.*

## Методология измерений (Benchmark)

Утилита `bfs_benchmark` выполняет по **10 измерений** для каждого алгоритма. На основе серии тестов рассчитываются:
* `Avg` — среднее время выполнения (именно оно используется в итоговых таблицах результатов).
* `Min` — минимальное время.
* `Max` — максимальное время.

**Особенности проведения замеров:**
* Время измеряется в микросекундах с помощью `clock_gettime()` и таймера `CLOCK_MONOTONIC`.
* Перед началом официальных измерений GraphBLAS проводится **прогревочный запуск**.
* Время построения матрицы GraphBLAS из структуры CSR **не учитывается** в итоговом времени работы алгоритмов поиска, так как матрица создаётся однократно перед серией замеров.

## Тестирование и верификация

Тестовый набор запускается отдельно от бенчмарков производительности:
```bash
ctest
```

Также доступны отдельные исполняемые файлы для кастомного запуска:
```bash

./test_comparison
```
> **Текущий статус:** Все предусмотренные тесты успешно пройдены (**100% passed**).

### Что проверяется в тестах
1. **Изолированная проверка реализаций** (на фиксированных тестовых топологиях):
   * Достижимость вершин и корректность вычисленных уровней BFS.
   * Правильность работы многопоточного/многоисточникового обхода (*Multisource BFS*).
   * Структурная корректность массива `parent` (отсутствие циклов в дереве родителей, валидность корневой вершины).
   * Наличие непрерывной цепочки родителей от каждой посещённой вершины к её исходному источнику.
2. **Перекрёстная (cross-validation) проверка:**
   * **Single-source:** Классический CSR-обход и GraphBLAS запускаются на одинаковых графах из одной и той же вершины. Полученные векторы уровней сравниваются поэлементно.
   * **Multi-source:** Выполняется аналогичное покомпонентное сравнение векторов при идентичном наборе начальных вершин-источников.

*Примечание: Успешное прохождение тестового набора гарантирует соответствие двух разных подходов на заложенных сценариях, но не является математическим доказательством корректности для абсолютно любых произвольных графов.*

### Анализ эффективности однократного обхода
Для сопоставления производительности однократного BFS используется отношение времени работы классического подхода к матричному:

\[\text{Ratio} = \frac{\text{Classic Parent BFS}}{\text{GraphBLAS Level BFS}}\]

* **\(\text{Ratio} > 1\):** Реализация на GraphBLAS работает быстрее классического обхода на базе CSR.
* **\(\text{Ratio} < 1\):** Классический алгоритм на базе CSR оказывается эффективнее.

Проведенные измерения наглядно демонстрируют, что **GraphBLAS не имеет монопольного или стабильного преимущества** по времени выполнения на всех типах исследованных графов:

* **Превосходство GraphBLAS:** Ярко выражено на плотных крупномасштабных графах социальных сетей. Для `com-Orkut` матричный BFS выполняется всего за **542.795 мс** против **2121.789 мс** у классического обхода. Схожая картина наблюдается для `soc-LiveJournal1`, где многоисточниковый GraphBLAS BFS отрывается от CSR-варианта более чем в 4 раза (**390.446 мс** против **1662.308 мс**).
* **Превосходство Classic CSR:** Наблюдается на разреженных структурах, графах цитирований и дорожных сетях (`road_usa`, `roadNet-CA`, `cit-Patents`). На дорожной карте США (`road_usa`) классический многоисточниковый BFS отрабатывает за субмиллисекундные **0.491 мс**, в то время как GraphBLAS затрачивает **36.194 мс**.

>  **Важное замечание:** Данный эксперимент не ставил целью замерять динамические размеры фронтов BFS, распределение вычислительного времени между отдельными уровнями или специфичные топологические метрики. В связи с этим влияние локальной ширины фронта, степени параллелизма подкапотных ядер и других свойств топологии в рамках данного отчета не фиксируется как строго доказанная причина разницы в физическом времени выполнения.

## Вывод

1. В проекте успешно реализованы и сопоставлены четыре вариации алгоритма BFS: классический однократный parent-BFS, классический multisource BFS, GraphBLAS Level BFS и GraphBLAS Multisource BFS.
2. Классические подходы базируются на явном управлении очередью вершин поверх статического **CSR-представления**. Варианты на GraphBLAS полностью перекладывают обход на **матрично-векторные операции** с использованием булева полукольца `LOR-LAND`.
3. Самостоятельное написание измеряемых алгоритмов позволило исключить побочные внутренние оптимизации высокоуровневых библиотек (таких как LAGraph или BGL), предоставив обеим концепциям абсолютно идентичные структуры входных данных и среду выполнения.
4. **Главный практический вывод:** При проектировании систем обработки больших графов нельзя слепо полагаться на бренд или технологический стек GraphBLAS как на универсальный ускоритель. Выбор между классическим обходом списков смежности и алгебраическим подходом должен опираться на предварительное профилирование и замеры времени выполнения непосредственно на целевом типе входных данных.

Корректность алгоритмов полностью верифицирована тестовым набором на базе `ctest` со статусом **100% passed**. Проверены достижимость, отсутствие циклов в дереве родителей, корректность уровней, а также проведено строгое покомпонентное сравнение выходных векторов двух кардинально различающихся подходов.
