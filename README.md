# Сравнение BFS: Classic vs GraphBLAS

## О проекте

В данном проекте реализованы и протестированы два варианта алгоритма обхода графа в ширину (BFS):

* **Классический BFS**: на основе очереди и CSR-представления графа.
* **BFS на основе линейной алгебры**: через библиотеку **SuiteSparse:GraphBLAS**.

## Программа:

* Загружает граф из файла .mtx (можно изменить в main.c)
* Находит вершину с максимальной степенью
* Выбирает равномерно распределённые по графу вершины для обхода(всего 4 вершины)
* Запускает 4 реализации BFS с замером времени:
classic_parent_bfs,
classic_multisource_bfs,
graphblas_level_bfs,
graphblas_multisource_level_bfs.
* Тесты запускаются отдельно

## CSR-формат (Compressed Sparse Row)

Для эффективного хранения больших разреженных графов в программе используется **CSR (Compressed Sparse Row)** — формат, который позволяет компактно хранить списки смежности вершин в двух массивах целых чисел:

- `row_ptr` — массив длины `(n + 1)`, где `n` — число вершин. Элемент `row_ptr[i]` указывает на начало списка соседей вершины `i` в массиве `col_idx`. А `row_ptr[i+1]` — на конец этого списка.
- `col_idx` — массив, в котором подряд записаны все соседи всех вершин.


## Реализованные операции

##  BFS с построением дерева обхода (parent BFS)

### Classic версия
Обход в ширину с использованием стандартной очереди.

```c
void csr_parent_bfs(CSRMatrix* csr, int start_vertex, int* parent)
```

**Параметры:**
* `csr` — граф в CSR-формате
* `start_vertex` — стартовая вершина
* `parent` — массив родителей

### Версия GraphBLAS
Итеративное умножение вектора фронта на матрицу смежности графа.

```c
int graphblas_level_bfs(CSRMatrix* csr, void* A_handle, int start_vertex, int* level)
```

**Параметры:**
* `csr` — граф в CSR-формате
* `A_handle` - матрица GraphBLAS (построенная заранее)
* `start_vertex` — стартовая вершина
* `level` — массив расстояний (заполняется функцией)

---

##  Multi‑source BFS

### Classic версия
Использует обычную очередь, но изначально в неё добавляются все заданные источники.

```c
void csr_multisource_bfs(CSRMatrix* csr, void* A_handle, int* sources, int num_sources, int* parent);
```

* **Принцип работы:** обход распространяется одновременно от всех источников. Родитель вершины - источник, который достиг её первым.
* **Особенности:** корректно работает на несвязных графах (каждый источник обходит свою компоненту связности).
* **Сложность:** Память — $O(V + E)$, Время — $O(V + E)$.

### Версия GraphBLAS
Вектор фронта инициализируется всеми источниками одновременно.

```c
int* graphblas_multisource_level_bfs(CSRMatrix* csr, int* sources, int num_sources, double* time_ms, int** level);
```

* **Принцип работы:** на каждой итерации выполняется умножение вектора фронта на матрицу смежности. Все новые вершины обрабатываются параллельно за одну матричную операцию.
* **Особенности:** на больших графах может быть эффективнее классической версии за счёт встроенного параллелизма.
* **Сложность:** Память — $O(V + E)$ + накладные расходы библиотеки GraphBLAS.

## Вспомогательные функции

* `load_matrix()` — загрузка графа из файла формата Matrix Market (.mtx).
* `graph_to_csr()` — преобразование графа из списков смежности в CSR-формат.
* `find_max_degree_vertex()` — поиск вершины с максимальной степенью.
* `delete_graph()` / `delete_csr()` — освобождение памяти.

### Установка SuiteSparse:GraphBLAS

#### Способ 1: Установка из исходников (рекомендуемый)
Этот способ гарантирует установку самой свежей версии библиотеки.

```bash
# Клонирование репозитория SuiteSparse
git clone https://github.com/DrTimothyAldenDavis/SuiteSparse.git
cd SuiteSparse/GraphBLAS
make
sudo make install

# Обновление кэша динамических библиотек
sudo ldconfig
```

После успешной установки компоненты будут доступны по путям:
* **Заголовочные файлы:** `/usr/local/include/suitesparse/GraphBLAS.h`
* **Библиотека:** `/usr/local/lib/libgraphblas.so`

#### Способ 2: Установка через пакетный менеджер (Ubuntu/Debian)
Быстрый способ установки стандартной версии из репозитория ОС:

```bash
sudo apt update
sudo apt install libsuitesparse-dev cmake build-essential
```

> **Примечание:** Пакетный менеджер вашей ОС может установить устаревшую версию библиотеки. Для получения максимальной производительности и актуальных функций используйте **Способ 1**.

mkdir build && cd build
cmake ..
make

## Бенчмарк

Программа `bfs_benchmark` выполняет **10 итераций** каждого алгоритма и вычисляет **среднее, минимальное и максимальное время** для статистической достоверности.

### Что измеряется:
- **Classic Parent BFS** — классический обход в ширину из одной вершины.
- **Classic Multisource BFS** — классический BFS из 4 равномерно распределённых источников.
- **GraphBLAS Level BFS** — обход в ширину через матрично-векторное умножение (один источник).
- **GraphBLAS Multisource Level BFS** — то же, но из 4 источников.

### Выходные данные:

После завершения всех итераций программа выводит таблицу:

| Metric(в мкс) | Avg | Min | Max |
| :--- | :--- | :--- | :--- |
| **Classic Parent BFS** | :--- | :--- | :--- |
| **Classic Multisource BFS** | :--- | :--- | :--- |
| **GraphBLAS Level BFS** | :--- | :--- | :--- |
| **GraphBLAS Multisource BFS** | :--- | :--- | :--- |

- **Avg** — среднее время за 10 запусков.
- **Min** — лучший (минимальный по времени) результат.
- **Max** — худший (максимальный) результат.

Затем программа вычисляет **ускорения (speedups)** между реализациями:

```text

Classic Multisource / Classic Parent: nx
GraphBLAS Multisource / GraphBLAS Level: nx
```

### Что такое «широкий» и «узкий» фронт BFS
Под «широким» фронтом понимается уровень BFS, содержащий тысячи и миллионы вершин (социальные сети). «Узкий» фронт — уровень с единицами или десятками вершин (дорожные сети). Ширина фронта определяет эффективность параллелизации.

## Анализ результатов

### 1. Большие ориентированные графы с широкими фронтами: победа GraphBLAS
`com-Orkut` (**5.45x**) и `soc-LiveJournal1` (**5.35x**) — это ориентированные социальные сети с огромным количеством рёбер (117M и 69M) и широкими фронтами BFS. Благодаря высокой степени вершин и направленным рёбрам, на каждом уровне BFS обрабатываются тысячи и миллионы вершин, что позволяет GraphBLAS эффективно распараллеливать вычисления через матрично-векторное умножение. Ускорение достигает 5–6 раз.

>  **Вывод:** На больших ориентированных графах с широкими фронтами GraphBLAS показывает кратное ускорение.

---

### 2. Неориентированные дорожные сети с узкими фронтами: победа классики
`road_usa` (**в 17.8x**) и `roadNet-CA` (**в 5.2x**) — это неориентированные дорожные сети с равномерной степенью вершин (3–4) и огромным диаметром. Фронты BFS здесь узкие — на каждом уровне обрабатывается всего несколько вершин. Параллелизм не даёт выигрыша, а накладные расходы GraphBLAS на создание матриц и синхронизацию потоков становятся критическими. Классика выигрывает с разрывом до 17.8x.

>  **Вывод:** На неориентированных структурированных графах с узкими фронтами и большим диаметром классический BFS значительно быстрее.

---

### 3. Ориентированный граф цитирования с узкими фронтами: победа классики
`cit-Patents` (**0.10x**) — ориентированный граф цитирования, но, в отличие от социальных сетей, его структура порождает узкие фронты BFS (степень вершин невысока, рёбра направлены от патентов к цитируемым). Это даёт преимущество классике (в 10.4x).

>  **Вывод:** Ориентированность графа не гарантирует победу GraphBLAS — решающую роль играет ширина фронтов.

---

### 4. Маленькие и средние ориентированные графы: победа классики
* **web-Google (0.99x)** — ориентированный веб-граф среднего размера, где результаты почти равны. Накладные расходы GraphBLAS и классики сопоставимы.
* **com-Amazon (0.63x)** — маленькая ориентированная социальная сеть (0.33M вершин). Накладные расходы GraphBLAS не окупаются, и классика выигрывает в 1.6x.

>  **Вывод:** На ориентированных графах среднего и малого размера, особенно с узкими фронтами, классика остаётся эффективнее.

---

### Иерархия факторов выбора алгоритма

1. **Ширина фронтов BFS** — самый важный фактор.
   - Широкие фронты → **GraphBLAS**
   - Узкие фронты → **Классика**

2. **Размер графа** (количество рёбер) — второй по значимости.
   - Огромные графы (> 50M рёбер) → GraphBLAS **может** окупиться (при широких фронтах)
   - Маленькие и средние (< 5M рёбер) → **Классика**

3. **Топология** — наименее важный фактор (она влияет на ширину фронтов).
   - Социальные сети → обычно широкие фронты → GraphBLAS
   - Дорожные сети → всегда узкие фронты → Классика
   - Графы цитирования → часто узкие фронты → Классика
     
###  Общий вывод
*  **GraphBLAS** максимально эффективен на больших ориентированных графах с широкими фронтами (`com-Orkut`, `soc-LiveJournal1`).
*  **Классика** побеждает на неориентированных структурированных графах с узкими фронтами и большим диаметром (`road_usa`, `roadNet-CA`), а также на ориентированных графах с узкими фронтами (`cit-Patents`) и маленьких графах (`com-Amazon`).

**Главный итог:** Универсального решения нет — выбор алгоритма зависит от топологии, ширины фронтов и размера конкретного графа. Ориентированность сама по себе не является гарантией эффективности GraphBLAS.
